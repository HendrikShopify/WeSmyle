# Components

Snippet conventions and the parameter table. One snippet per Figma component, same name. See `docs/FIGMA-TO-CODE.md` for the contract.

## Testing

`npm run gallery` renders each snippet's full Figma variant matrix to `tests/gallery/<name>.html` with LiquidJS (`tests/render.js`), builds the real theme CSS plus hooks that force `:hover` and `:focus-visible` (`tests/gallery.input.css`), and screenshots every page (`tests/shot.js`). Compare the PNG with the Figma component set. Fixtures live in `tests/fixtures/<name>.json`: the matrix, default params and extra cases. Shopify filters are stubbed in `render.js`; keep the stubs plausible, not real.

Definition of done for a snippet: header comment with Figma name and parameters, defaults equal the Figma default variant, tokens only, gallery matches Figma, old CSS for it removed, Code Connect mapped, row added below.

## Hiding from JS

Use the HTML `hidden` attribute (`el.hidden = true`), never the `hidden` class. Tailwind v4 emits `.flex` and `.inline-flex` after `.hidden`, so the class loses on any element that has a display utility. `[hidden]` is `display: none !important` in the preflight and always wins. Snippets expose `attributes` so the parent can render the initial `hidden`.

## Section rendering targets

### Icons

Every UI icon in `assets/icon__*.svg` is an export of the matching Figma `icon/*` component: 24-unit viewBox, no width/height, `stroke="currentColor"`, no stroke-width attribute (the weight comes from the `icon.stroke` token), `aria-hidden="true" focusable="false"`. Some files are aliases kept for existing snippet calls (`account` = `user`, `cart` = `shopping-bag`, `close` = `x`, `min` = `minus`, `error` = `circle-alert`, `success` = `circle-check`, `discount` = `tag`, `delete` and `remove` = `trash-2`). Size them with a wrapper class (`size-4`, `size-5`, `size-6`), never inline SVG in a snippet. Social icons and `icon__star` are fill icons and keep their own geometry.

When Shopify section rendering replaces markup (cart icon, cart drawer), the section file wraps the snippet in the element whose id the JS looks for, and the header renders the same snippet inside the same id. The snippet itself carries no id. Listeners on replaced elements must be delegated to a stable parent (see `CartIcon` in cart.js).

## Images

Always go through `media`. Never write `<img srcset>` by hand. The parent passes `sizes` that matches its layout (`25vw` for a 4-column grid, `100vw` for a hero) and `loading: 'eager'` only for the first media in the viewport. Shopify's `image_tag` takes attributes as named parameters (`class:`, `loading:`), not an attribute string.

## Form fields

Inputs, textareas and selects fill their container; the parent sets the width. A field is composed by the parent: `field-label` + control + `helper-text`, linked with `for`, `id` and `describedby`. Error is passed as `error: true` on the control and `type: 'error'` on the helper; the snippets never decide validity.

## Class names must appear literally

Tailwind only generates classes it finds as complete strings in the source. Never build a class from two strings in Liquid (`'[&>svg]:' | append: size` produces nothing). Put the full class in each `case` branch instead.

## Scripts

Component scripts that cards and sections depend on anywhere (product-form.js, wishlist.js, variant-selects.js, custom-select.js) load in `layout/theme.liquid`, not in a section. A section-level script only exists for the section that owns it.

## State attributes from JS

Tailwind's attribute variants match exact values. Set `aria-busy="true"` with `setAttribute`, never `toggleAttribute` (which writes an empty value). Same for any `data-*` state a snippet styles on: write the value the snippet's classes expect.
